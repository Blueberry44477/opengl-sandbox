## 1. Вступ: Чому все так складно?

У старому OpenGL (версії 1.x / 2.x, так званий *Immediate Mode* або *Fixed-Function Pipeline*) намалювати трикутник можна було кількома викликами функцій:

```cpp
// ЗАСТАРІЛИЙ ПІДХІД (Immediate Mode — не використовується в сучасному 3D!)
glBegin(GL_TRIANGLES);
    glVertex3f(-0.5f, -0.5f, 0.0f);
    glVertex3f( 0.5f, -0.5f, 0.0f);
    glVertex3f( 0.0f,  0.5f, 0.0f);
glEnd();
```

Цей підхід був простим, але вкрай неефективним: кожна вершина передавалася з центрального процесора (CPU) на графічний процесор (GPU) окремо при кожному кадрі.

**Сучасний OpenGL (Core Profile):**
- Не дозволяє використання фіксованого конвеєра та функцій `glBegin`/`glEnd`.
- Вимагає, щоб розробник самостійно завантажив дані вершин у відеопам'ять GPU (**VRAM**) заздалегідь.
- Вимагає обов'язкового написання власних програм для GPU — **шейдерів** мовою **GLSL**.
- Вимагає визначення формату пам'яті через **VAO** (Vertex Array Object).

Нагорода за цю складність — колосальна швидкість: GPU може паралельно обробляти мільйони трикутників за частку мілісекунди.

## 2. Графічний конвеєр (Graphics Pipeline)

Графічний конвеєр — це послідовність кроків, через які проходять вхідні 3D-координати, перетворюючись на 2D-пікселі на моніторі.

```
+-------------------------------------------------------------+
|                1. Вхідні вершини (Vertex Data)              |
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
|        2. Вершинний шейдер (Vertex Shader) [Програмований]   |
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
| 3. Збирання примітивів (Shape Assembly / Primitive Assembly)|
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
|      4. Геометричний шейдер (Geometry Shader) [Опціональний]|
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
|                5. Растеризація (Rasterization)              |
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
|      6. Фрагментний шейдер (Fragment Shader) [Програмований]|
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
|       7. Тести та змішування (Tests & Blending / Output)    |
+-------------------------------------------------------------+
```

1. **Vertex Data:** Масив координат точок у просторі (наприклад, 3 вершини нашого трикутника).
2. **Vertex Shader:** Виконується окремо для *кожної* вершини. Головна мета — перетворити вхідні координати у фінальні нормалізовані координати простору відсікання (`gl_Position`).
3. **Primitive Assembly:** З'єднує вершини у геометричні примітиви (в нашому випадку — `GL_TRIANGLES`).
4. **Rasterization:** Перетворює суцільний геометричний трикутник на дискретну сітку пікселів (фрагментів) на екрані, відсікаючи все, що виходить за межі екрана.
5. **Fragment Shader:** Виконується для *кожного* згенерованого пікселя (фрагмента). Головна мета — визначити кінцевий колір пікселя (RGBA).
6. **Tests & Blending:** Перевіряє тест глибини (Depth Test), трафарет (Stencil Test) та змішує напівпрозорі кольори перед записом у кадровий буфер.

## 3. Нормалізовані координати пристрою (NDC)

OpenGL очікує, що координати всіх видимих вершин лежать у діапазоні від `-1.0` до `1.0` по всіх трьох осях ($x, y, z$). Цей простір називається **Normalized Device Coordinates (NDC)**.

```
              Y = +1.0 (Верх)
                   |
                   |   (0.0, 0.5)
                   |       /\
                   |      /  \
                   |     /    \
                   |    /      \
 (-0.5, -0.5)      |   /________\     (0.5, -0.5)
-------------------+------------------- X = +1.0 (Право)
X = -1.0 (Ліво)    |      (0.0, 0.0)
                   |
                   |
              Y = -1.0 (Низ)
```

- `( 0.0,  0.5, 0.0)` — верхня середня точка;
- `(-0.5, -0.5, 0.0)` — нижня ліва точка;
- `( 0.5, -0.5, 0.0)` — нижня права точка.

Координата $Z = 0.0$, оскільки трикутник лежить у площині екрана. Функція `glViewport` згодом автоматично трансформує цей діапазон `[-1.0, 1.0]` у реальні пікселі вікна (наприклад, `800x600`).

## 4. Буфери та пам'ять GPU: VBO та VAO

Щоб GPU міг швидко намалювати трикутник, ми повинні розмістити масив вершин у пам'яті самої відеокарти. Для цього використовуються об'єкти **VBO** та **VAO**.

### VBO (Vertex Buffer Object)

**VBO** — це буфер у відеопам'яті (VRAM), куди копіюється масив вершин із системної оперативної пам'яті (RAM).

```cpp
float vertices[] = {
    -0.5f, -0.5f, 0.0f,
     0.5f, -0.5f, 0.0f,
     0.0f,  0.5f, 0.0f
};

unsigned int VBO;
glGenBuffers(1, &VBO); // Створюємо ідентифікатор буфера
glBindBuffer(GL_ARRAY_BUFFER, VBO); // Робимо його активним масивом вершин
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW); // Копіюємо байти в пам'ять GPU
```

Прапорець `GL_STATIC_DRAW` підказує драйверу GPU, що дані записуються один раз і будуть використовуватися дуже багато разів для малювання (що дозволяє GPU вибрати найоптимальнішу секцію пам'яті).

---

### VAO (Vertex Array Object)

**VAO** — це контейнер, який зберігає:
1. Прив'язку буфера `GL_ARRAY_BUFFER` (VBO).
2. Налаштування вершинних атрибутів (`glVertexAttribPointer`).
3. Стан увімкнення атрибутів (`glEnableVertexAttribArray`).

У сучасному **Core Profile** наявність зв'язаного VAO є **обов'язковою**! Без зв'язаного VAO OpenGL взагалі відмовиться малювати.

```cpp
unsigned int VAO;
glGenVertexArrays(1, &VAO); // Створюємо VAO
glBindVertexArray(VAO);     // Прив'язуємо його перед налаштуванням атрибутів
```

---

### Зв'язування атрибутів: `glVertexAttribPointer`

GPU не знає структуру байтів усередині VBO: чи це 3 числа `float`, чи 2, чи є там кольори чи текстурні координати. Функція `glVertexAttribPointer` пояснює відеокарті, як інтерпретувати масив байтів:

```cpp
glVertexAttribPointer(
    0,                  // location: індекс атрибута у вершинному шейдері (layout (location = 0))
    3,                  // розмір атрибута: 3 компоненти (X, Y, Z)
    GL_FLOAT,           // тип кожного компонента: 32-бітний float
    GL_FALSE,           // чи потрібно нормалізувати цілі числа до [-1, 1] або [0, 1]
    3 * sizeof(float),  // крок (stride): розмір однієї повної вершини в байтах
    (void*)0            // зміщення (offset): з якого байта починається цей атрибут
);
glEnableVertexAttribArray(0); // Вмикаємо атрибут з індексом 0
```

Після цього зв'язок надійно зафіксовано у поточному VAO. Ми можемо відв'язати VBO та VAO:

```cpp
glBindBuffer(GL_ARRAY_BUFFER, 0); // Безпечно відв'язати VBO
glBindVertexArray(0);             // Відв'язуємо VAO
```

## 5. Шейдери та мова GLSL

Шейдери пишуться мовою **GLSL (OpenGL Shading Language)** і компілюються динамічно під час запуску програми вашим графічним драйвером.

### Вершинний шейдер (Vertex Shader)

```glsl
#version 410 core
layout (location = 0) in vec3 aPos;

void main() {
    gl_Position = vec4(aPos.x, aPos.y, aPos.z, 1.0);
}
```

- `#version 410 core`: версія GLSL, що відповідає OpenGL 4.1 Core Profile.
- `layout (location = 0) in vec3 aPos;`: вхідний вектор із 3 чисел `float`, що відповідає `location = 0` у виклику `glVertexAttribPointer`.
- `gl_Position`: вбудована службова змінна векторного типу `vec4` (гомогенні координати $x, y, z, w$). Оскільки ми малюємо в 2D, задаємо $w = 1.0$.

---

### Фрагментний шейдер (Fragment Shader)

```glsl
#version 410 core
out vec4 FragColor;

void main() {
    FragColor = vec4(1.0f, 0.5f, 0.2f, 1.0f); // Насичений помаранчевий колір (RGBA)
}
```

- `out vec4 FragColor;`: вихідний колір фрагмента (пікселя) у форматі `(Червоний, Зелений, Синій, Альфа/Прозорість)` у діапазоні від `0.0` до `1.0`.

---

### Компіляція та лінкування шейдерної програми

Процес дуже нагадує компіляцію C++: окремі файли компілюються в об'єктні модулі, а потім лінкуються у виконувану програму.

```cpp
// 1. Компіляція вершинного шейдера
unsigned int vertexShader = glCreateShader(GL_VERTEX_SHADER);
glShaderSource(vertexShader, 1, &vertexShaderSource, nullptr);
glCompileShader(vertexShader);

// 2. Компіляція фрагментного шейдера
unsigned int fragmentShader = glCreateShader(GL_FRAGMENT_SHADER);
glShaderSource(fragmentShader, 1, &fragmentShaderSource, nullptr);
glCompileShader(fragmentShader);

// 3. Створення програми та лінкування
unsigned int shaderProgram = glCreateProgram();
glAttachShader(shaderProgram, vertexShader);
glAttachShader(shaderProgram, fragmentShader);
glLinkProgram(shaderProgram);

// 4. Видалення проміжних об'єктів шейдерів після лінкування
glDeleteShader(vertexShader);
glDeleteShader(fragmentShader);
```

У нашому коді [`main.cpp`](file:///Users/blueberry/workspace/programming/graphics-programming/learning/opengl-sandbox/main.cpp) функція `createShaderProgram` містить перевірку помилок компіляції (`glGetShaderiv`) та лінкування (`glGetProgramiv`), що виводить детальний звіт у консоль у разі синтаксичної помилки в GLSL.

## 6. Цикл рендерингу (Render Loop)

Цикл рендерингу виконується кожного кадру (зазвичай 60 або більше разів на секунду):

```cpp
while (!glfwWindowShouldClose(window)) {
    // 1. Обробка подій клавіатури (наприклад, натискання ESC для виходу)
    processInput(window);

    // 2. Очищення екрана кольором тла
    glClearColor(0.1f, 0.2f, 0.3f, 1.0f);
    glClear(GL_COLOR_BUFFER_BIT);

    // 3. Активація нашої шейдерної програми
    glUseProgram(shaderProgram);

    // 4. Прив'язка налаштованого VAO нашого трикутника
    glBindVertexArray(VAO);

    // 5. Виклик малювання: 1 трикутник, починаючи з 0-ї вершини, всього 3 вершини
    glDrawArrays(GL_TRIANGLES, 0, 3);

    // 6. Подвійна буферизація та опитування подій ОС
    glfwSwapBuffers(window);
    glfwPollEvents();
}
```

### Подвійна буферизація (Double Buffering)
- **Front Buffer (Передній буфер):** Буфер, який прямо зараз відображається на екрані монітора.
- **Back Buffer (Задній буфер):** Буфер, у якому OpenGL зараз малює наступний кадр.
- `glfwSwapBuffers(window)` миттєво міняє їх місцями, запобігаючи мерехтінню екрана та артефактам розриву зображення (screen tearing).

## 7. Особливості роботи на macOS (Retina та Core Profile)

1. **Версія OpenGL на macOS:**
   Компанія Apple оголосила OpenGL застарілим на користь власного Metal API, тому найновіша підтримувана версія OpenGL на macOS — **4.1**.
   Саме тому ми вказуємо версію 4.1 та Core Profile:
   ```cpp
   glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 4);
   glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 1);
   glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);
   glfwWindowHint(GLFW_OPENGL_FORWARD_COMPAT, GL_TRUE); // Обов'язково для macOS!
   ```

2. **Придушення попереджень про застарілість:**
   На початку `main.cpp` визначено `#define GL_SILENCE_DEPRECATION`, що вимикає попередження компілятора AppleClang про застарілий статус OpenGL.

3. **Retina Display (HiDPI):**
   На екранах Retina вікно розміром `800x600` екранних точок насправді має кадровий буфер `1600x1200` фізичних пікселів.
   Щоб зображення не виявилося в кутку екрана, ми використовуємо `glfwGetFramebufferSize` та колбек `framebuffer_size_callback`:
   ```cpp
   void framebuffer_size_callback(GLFWwindow* window, int width, int height) {
       glViewport(0, 0, width, height);
   }
   ```
